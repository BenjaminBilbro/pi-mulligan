## Goal

**Feature Goal**: Ship `src/log.ts` — the structured, append-only JSONL logger that is Mulligan's primary observability surface in non-TUI modes (spec/04 §9) and the assertion target of the test suite (spec/10). It is OFF by default, opens lazily on first write, and is fail-open: a bad path or un-serializable payload can never crash the agent loop (spec/03 #4, spec/09 §4).

## Why

- This is the observability backbone for every event in the extension. CONTRACT §4 lists the consumers: `log(...)` is called by filter.ts (P1.M3.T2), every tool in tools/* (P1.M4.T1–T4), nudges.ts (P1.M3.T3), and markers.ts (P1.M3.T1) for every significant event. Without log.ts, those modules have no fail-safe diagnostic channel.
- Establishes the **fail-open / never-throw** contract (spec/03 principle #4, spec/08 E13) at the observability layer: a logger that can throw would itself be a way to break the agent loop, which is the one thing Mulligan must never do. This task makes that guarantee concrete.
- Resolves the one genuinely open architectural question (CONTRACT §2): config.ts must NOT import log.ts (and it doesn't — T2 already uses `console.warn` directly for its `warnConfig`). So log.ts must NOT create the cycle by importing config.ts either. The clean design (proven in the sibling oracle): **log.ts holds its OWN destination via `setLogFile()`** — it imports nothing from config. `index.ts` (a LATER task, P1.M7.T1) is the sole place that wires them together: `setLogFile(getConfig().log.file)` after config load. This also sidesteps a chicken-and-egg timing bug (the log path comes FROM the config that is under validation). This task ships the logger + its test ONLY; it does NOT touch index.ts.

### Success Criteria
- [ ] Exports `type Level = "debug" | "info" | "warn" | "error"` and `interface LogLine { ts: string; level: Level; event: string; sessionId: string; data?: unknown }` EXACTLY per spec/04 §9.
- [ ] Exports `function setLogFile(path: string | null): void` — sets/replaces the module-level log destination, or `null` to disable. Assigning a string must NOT throw and must NOT eagerly open the file (open is deferred to first write).
- [ ] Exports `function log(level, event, sessionId, data?): void` — the pure-string-sessionId form (CONTRACT §3 permits passing sessionId directly for the pure case; it matches the LogLine `sessionId: string` field and is unit-testable without a Pi context object).
- [ ] When `logFile === null` (the default), `log()` returns immediately — a pure no-op that writes nothing and creates no file. `log()` never throws in this state.
- [ ] When a destination IS set, each `log()` call appends exactly one line = `JSON.stringify({ts, level, event, sessionId, data}) + "\n"` via `node:fs appendFileSync(dest, line, "utf8")`. `ts` = `new Date().toISOString()` (ISO 8601 UTC, ends with `Z`).
- [ ] Append-only: successive calls accumulate lines; a pre-existing file's content is never truncated/overwritten (true append).
- [ ] `data` is OPTIONAL: when not provided (undefined), JSON.stringify DROPS the `data` key from the line (no `"data"` key present). When `data` is an explicit `null`, it is preserved as a real JSON `null` (`null` is a provided value). When `data` is an object/array, it is serialized faithfully.
- [ ] Fail-open (spec/03 #4, spec/09 §4): `log()` NEVER throws. The `JSON.stringify(line)` AND `appendFileSync(...)` calls share one `try/catch`; on ANY error (bad path → ENOENT/EISDIR/EACCES/ENOSPC; circular data → TypeError; BigInt data → TypeError) a short human-readable note is written to `process.stderr` and the error is swallowed. The stderr write is itself wrapped in its own `try/catch` so even a failing stderr write cannot throw.
- [ ] A failed write does NOT leave a partial/corrupt line in the file: because `JSON.stringify` runs BEFORE `appendFileSync` inside the same try, a serialization failure aborts before any bytes are written; a filesystem failure on a valid string may write a partial line, but no second `appendFileSync` is attempted and no throw escapes.
- [ ] Exports convenience helpers `logInfo`, `logDebug`, `logWarn`, `logError` that each curry the level and delegate to `log()` (so all behavior — no-op, fail-open, append-only — is shared).
- [ ] `npx tsc --noEmit` passes with zero errors (strict + noImplicitAny satisfied).
- [ ] `npx vitest run test/log.test.ts` is fully green (all CONTRACT §6 cases + LogLine-shape + append-only + fail-open + no-op-when-null + stderr-fallback).
- [ ] Scope honored (manual Level-4, NOT shell gates): src/log.ts imports NOTHING from config.ts, NOTHING from @earendil-works/pi-coding-agent, and NOTHING else except `node:fs`; NO wiring is added to index.ts (the `setLogFile(getConfig().log.file)` call belongs to the index.ts task); the module is fully unit-testable with no Pi.

### Implementation Patterns & Key Details
```ts
export function log(level: Level, event: string, sessionId: string, data?: unknown): void {
  const dest = logFile;
  if (dest === null) return;                 
  const line: LogLine = { ts: new Date().toISOString(), level, event, sessionId, data };
  try {
    appendFileSync(dest, JSON.stringify(line) + "\n", "utf8");
  } catch (err) {
    writeStderrFallback(dest, level, event, err);
  }
}
function writeStderrFallback(dest: string, level: Level, event: string, err: unknown): void {
  try {
    process.stderr.write(`[mulligan] log: write failed (event=${event} level=${level} dest=${dest}): ${String(err)}\n`);
  } catch {
  }
}
```
