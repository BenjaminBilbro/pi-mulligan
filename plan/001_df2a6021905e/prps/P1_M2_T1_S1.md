## Why

- This is the FIRST correctness surface of Milestone M2 (the pure, zero-Pi, fully unit-tested core). Every consumer depends on these numbers: `tools/audit.ts` (P1.M4.T4) calls `estimateTokens` per-message over `runtime.lastFiltered` to render the filtered-view breakdown; `nudges.ts` (P1.M3.T3) calls `resultBytes`/`approxTokens` on `tool_result` content for the bloat reminder and `estimateTokens` at `turn_end` for the drift `deltaTokens`.
- D5 (honest bookkeeping): the audit MUST compute tokens from the *filtered* view, NEVER `ctx.getContextUsage()` (which counts hidden tokens). That mandate is only satisfiable if a cheap, deterministic, pure estimator exists — this module is it.
- spec/07 §1 is explicit that the bloat threshold is in **BYTES** of the in-context UTF-8 text representation, deliberately below Pi's 50 KB built-in cap — so a byte-level measurer (`resultBytes`) distinct from the char/token estimator is required, plus a byte→token converter (`approxTokens`) for the persisted turn-metric.
- Zero-import design: by importing NOTHING (not even `type` from config.ts), the module is maximally testable and creates no build-order coupling. The local `TokenConfidence` is structurally identical to config.ts's exported `EstimateConfidence`, so the audit tool mixes the two with no cast.

## What

A single TypeScript module + its test. No Pi surface, no session, no model, no I/O, no module-scoped mutable state. The module exposes three pure functions and one ratio:

- `estimateTokens(messages: MessageLike[] | null | undefined, _model?: unknown): TokenEstimate` — sums each message's stringified content character length, returns `{ tokens: Math.ceil(totalChars / CHARS_PER_TOKEN), confidence: "medium" }`. `model` accepted, v1-unused.
- `resultBytes(content: ResultContentBlock[] | null | undefined): number` — UTF-8 BYTE length of `text` blocks (`Buffer.byteLength(text, "utf8")`) + base64 char-length of `image` blocks; unknown types / non-records contribute 0.
- `approxTokens(bytes: number): number` — `Math.ceil(bytes / CHARS_PER_TOKEN)`; NaN/±Infinity/negative → 0.
- `CHARS_PER_TOKEN = 4` (exported; the OpenAI "~4 chars ≈ 1 token" rule of thumb).

### Implementation Patterns & Key Details
```ts
export function estimateTokens(messages: MessageLike[] | null | undefined, _model?: unknown): TokenEstimate {
  const list = Array.isArray(messages) ? messages : [];
  let chars = 0;
  for (const msg of list) chars += messageCharLength(msg);
  return { tokens: Math.ceil(chars / CHARS_PER_TOKEN), confidence: DEFAULT_TOKEN_CONFIDENCE };
}
export function resultBytes(content: ResultContentBlock[] | null | undefined): number {
  if (!Array.isArray(content)) return 0;
  let bytes = 0;
  for (const block of content) {
    if (!isRecord(block)) continue;
    const type = readOwn(block, "type");
    if (type === "text")       bytes += stringByteLength(readOwn(block, "text"));   
    else if (type === "image") bytes += stringLength(readOwn(block, "data"));       
  }
  return bytes;
}
export function approxTokens(bytes: number): number {
  if (!Number.isFinite(bytes) || bytes < 0) return 0;
  return Math.ceil(bytes / CHARS_PER_TOKEN);
}
function readOwn(obj: unknown, key: string): unknown {
  if (!isRecord(obj)) return undefined;
  try { return obj[key]; } catch { return undefined; }
}
function safeStringLength(value: unknown): number {
  try { const s = JSON.stringify(value); return typeof s === "string" ? s.length : 0; } catch { return 0; }
}
function stringByteLength(value: unknown): number {
  return typeof value === "string" ? Buffer.byteLength(value, "utf8") : 0;
}

```
