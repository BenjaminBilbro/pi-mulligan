# PRP for P1.M4.T3.S1

## Objective

Implement the `mulligan_checkpoint` tool's `execute()` in `src/tools/checkpoint.ts` (currently an `export {};` stub): a thin, typebox-schema'd, fail-open adapter that (1) gates on the master config.enabled switch (E14), (2) validates the checkpoint name against /^[a-z0-9_-]{1,40}$/ (E10), (3) delegates the single write to the already-shipped `setCheckpoint(pi, ctx, name)` (markers.ts, P1.M3.T1.S1) which calls `pi.setLabel(ctx.sessionManager.getLeafId(), "mulligan:checkpoint:"+name)`, and (4) returns the verbatim spec/05 §3 success text naming the entry id + a rewind usage hint. Never throws (E13); every return path carries a `details` object (GOTCHA #4). `pi` is captured via the `makeCheckpointTool(pi)` factory closure. Also create the implicit-TDD unit suite `test/tools/checkpoint.test.ts` mirroring the shrink.test.ts idiom.

## Context

## Goal

**Feature Goal**: Ship the third of Mulligan's four agent-callable tools — `mulligan_checkpoint` — whose `execute()` tags the current session leaf with a `mulligan:checkpoint:<name>` Pi label so a later `mulligan_rewind(granularity:"checkpoint")` can target it precisely. The tool validates the checkpoint name, delegates the single write to the already-shipped `setCheckpoint` wrapper, and returns the verbatim spec success text naming the entry id + a rewind usage hint.

**Deliverable**: `src/tools/checkpoint.ts` replacing the current `export {};` stub — a thin, typebox-schema'd, fail-open `makeCheckpointTool(pi)` factory exposing a `ToolDefinition<typeof CheckpointParams, CheckpointDetails>`. Plus the implicit-TDD unit suite `test/tools/checkpoint.test.ts`.

**Success Definition**: `npx tsc --noEmit` passes; the new unit suite is green; the full existing suite (532 tests) still passes; the tool never throws; every return path carries a `details` object; the LLM-facing name/label/description/parameters match spec/05 §3+§5 verbatim; `pi.setLabel` is called with `(leafId, "mulligan:checkpoint:<name>")` on the happy path and never on any refusal.

## Why

- **Closes the checkpoint loop.** `mulligan_rewind`'s `granularity:"checkpoint"` mode (shipped in P1.M4.T1.S1) resolves a rewind target by finding a `mulligan:checkpoint:<name>` label on the branch. Without this tool, no label is ever created, so checkpoint-mode rewind has nothing to target. This tool is the *only* producer of those labels.
- **Feasibility pre-proven.** spec/02 §C9 verified `pi.setLabel`/`getLabel` round-trip works from a tool. `setCheckpoint` (markers.ts, P1.M3.T1.S1) is already shipped and unit-tested; this tool is a thin validation+text adapter on top of it.
- **Minimal, consistent surface.** Mirrors the exact structural template of the sibling `mulligan_shrink`/`mulligan_rewind` tools (same factory-closure pattern, same `defineTool`/`AgentToolResult<T>`/`details`-on-every-path conventions) so the LLM sees a uniform tool family.

## What

A single new tool file + its test. The tool's `execute(toolCallId, params, signal, onUpdate, ctx)`:
1. Reads `getConfig()` once; if `config.enabled === false` → refuse "Mulligan is disabled" (E14). *(No checkpoint-specific sub-gate exists in MulliganConfig — only the master switch.)*
2. Validates `params.name` against `/^[a-z0-9_-]{1,40}$/`; non-match → refuse (E10).
3. Calls `setCheckpoint(pi, ctx, name)` (markers.ts), which calls `pi.setLabel(ctx.sessionManager.getLeafId(), "mulligan:checkpoint:" + name)` and returns the leaf id (or `null` if no leaf / setLabel threw — the wrapper is fail-open).
4. On success: returns the VERBATIM spec/05 §3 text substituting `<name>` and the returned entry id; `details.entryId === leafId`, `details.name === name`.
5. On `setCheckpoint` returning `null`: returns a refusal text naming the failure; never throws (E13).
6. The whole body is ONE try/catch → any unexpected exception becomes a refusal text (E13).

### Implementation Patterns & Key Details

```ts
async function checkpointExecute(
  pi: ExtensionAPI,
  _toolCallId: string,
  params: CheckpointArgs,
  _signal: AbortSignal | undefined,
  _onUpdate: unknown,
  ctx: ExtensionContext,
): Promise<AgentToolResult<CheckpointDetails>> {
  let name = "";                       
  try {
    const config = getConfig();        
    if (!config.enabled) return refusal("Mulligan is disabled", name);  
    name = params?.name ?? "";         
    if (typeof params?.name !== "string" || !NAME_RE.test(params.name)) {
      return refusal(
        "name must match /^[a-z0-9_-]{1,40}$/ (lowercase, digits, hyphen, underscore; max 40)",
        name,
      );                               
    }
    name = params.name;                
    const entryId = setCheckpoint(pi, ctx, name);   
    if (entryId === null) {            
      return refusal("could not set checkpoint (no current leaf or label write failed)", name);
    }
    const text =
      `Mulligan: checkpoint '${name}' set at entry ${entryId}. ` +
      `Rewind to it with mulligan_rewind(granularity:'checkpoint', checkpoint:'${name}').`;
    return { content: [{ type: "text", text }], details: { name, entryId } };
  } catch (e) {                        
    return refusal(`unexpected error: ${e instanceof Error ? e.message : String(e)}`, name);
  }
}

```
