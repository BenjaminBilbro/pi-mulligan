## 5. How it works
- The core insight (spec/02, spec/03 §1): Pi's conversation is an append-only tree an
  agent cannot structurally mutate from a tool, but the agent CAN drop persisted "view
  instructions" that the context event honors on every inference. A rewind is therefore
  not a deletion — it is a PERMANENT SOFT-DELETE: a persisted marker hides a span from
  every future inference while the originals stay on disk and visible in /tree.
- Data flow on a rewind (ASCII: appendEntry marker [not in context] + sendMessage note
  [in context] + tool confirmation → next inference context handler reads markers,
  rewrites the message copy, returns {messages} → model resumes, no resume code needed).
- Shrink = view substitution (marker substitutes content in place, preserving role /
  toolCallId / toolName / isError so the tool-call/result pairing invariant holds).
- Ride-along nudges (ZERO extra model requests): Nudge A (tool_result reminder >8192
  bytes) + Nudge B (per-turn drift nudge >3000 tokens, injected into the context copy,
  NEVER persisted).
- /tree is the audit trail: every rewind/shrink/checkpoint is a persisted entry; the
  human inspects the full un-filtered history via Pi's native /tree. Mulligan adds NO
  human-facing command (D8 — redundant with /tree /compact /fork).
## 6. Guarantees
1. Soft-delete / audit trail — hidden content is NEVER lost; stays in session JSONL on
   disk; visible in Pi's native /tree.
2. Fail-open — any internal error degrades to a logged no-op, never a broken agent turn.
   Every tool and handler is try/catch-wrapped.
3. Zero-config + zero extra requests — works out of the box with all defaults; the nudges
   ride inferences that were already happening (no added model calls).
## 7. Known limitations
(Mulligan is deliberately minimal. These are the things it deliberately does NOT do in v1.)
- Compaction leak (spec/08 E7): Pi's auto-compaction may summarize a span that included a
  Mulligan-hidden message → a transient "leak" via the summary until the next compaction.
  Bounded & transient; Mulligan reducing context makes compaction fire later.
- No marker garbage-collection (spec/08 E15): markers persist intentionally (they ARE the
  audit trail). rewind.maxDepth=5 bounds simultaneous ACTIVE rewind markers. Cost is disk
  growth only (markers are control state, NOT in context).
- Nudges are advisory (spec/08 E18 / D3): they never force behavior; cost is ~25–40 tokens
  per nudge when it fires.
- Per-tool bloat thresholds are FUTURE (system_context.md §7): v1 ships a single global
  nudges.bloatThresholdBytes=8192. Per-tool thresholds (e.g. a higher ceiling for `read`)
  are a documented post-v1 refinement, NOT in v1.
- No undo / un-rewind (spec/SPEC.md §9 D6): agent-initiated rewinds & shrinks persist
  across reload and /resume. A human who wants to explore hidden content uses /tree.
- Soft retry only, no replay (spec/SPEC.md §9 D1): hidden tool calls' side effects persist
  on disk (files written, commands run); replaying them would compound those effects.
  The mutation warning + the note's true_current_state + auto-appended file ledger are the
  safeguards.
