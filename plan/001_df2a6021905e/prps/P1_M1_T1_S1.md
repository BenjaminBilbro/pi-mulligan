## Why

- This is the dependency root of the ENTIRE pi-mulligan build (spec/11 §2 build order, Step 0). config.ts (T2), log.ts (T3), runtime.ts (T4), and the whole M2 pure core import from sibling modules inside `src/`; none of them can be created until the tree exists.
- Establishes the two load-bearing conventions every later file assumes: (a) TypeScript loaded via jiti at runtime (NO build step — `main:"src/index.ts"` points at `.ts` directly), and (b) `node_modules` is for editor IntelliSense only; Pi resolves `@earendil-works/pi-coding-agent` + `typebox` from its OWN install.
- Verifies the environment contract empirically: a no-op factory loads under Pi 0.84.1. The feasibility spike (`spec/reference/looper-smoke.proto.ts`) and the entire spec assume this surface works; this task makes it concrete.

## What

A greenfield scaffold. No application logic. No handler/tool registration (CONTRACT DEFINITION §3: "DO NOT register anything yet"). The `pi` object is received but unused at this stage. The deliverable is purely structural + a loadable entry point.
