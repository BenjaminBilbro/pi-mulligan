- This is the SECOND correctness surface of Milestone M2 (the pure, zero-Pi, fully unit-tested core), the sibling of `tokens.ts` (P1.M2.T1.S1, Complete). It is the **state-ledger** half of the confabulation defense (D/D17): the rewind note tells the resumed model the TRUE filesystem state of the abandoned span so it does not blindly redo side-effectful work (E5).
- spec/05 §1 step 5 + spec/04 §3: the rewind tool persists `ledger: FileLedger` into the `mulligan:rewind` marker and feeds it to `renderNote` (P1.M2.T3) so the note's `<files-read>`/`<files-modified>`/`<bash-side-effects>` blocks render. - The contract is explicit that this must be a **deterministic extraction** (NOT a model call — D2: the note redirects, it does not merely describe). The bash policy is the load-bearing design choice: it is **asymmetric** — `bashSideEffects` is HIGH-RECALL ("when in doubt, include", because a missed write is the dangerous failure E5) while `modifiedFiles`-from-bash is HIGH-PRECISION (only confident parseable paths). This asymmetry is what makes `git commit` land in `bashSideEffects` only (not `modifiedFiles`) — exactly the pinned example.
- Zero-import design: by importing NOTHING, the module is maximally testable and creates no build-order coupling to config/tokens/log. The local `MessageLike` is structurally compatible with a real Pi `AgentMessage[]` (a real list assigns in with no cast).

## What

A single TypeScript module + its test. No Pi surface, no session, no model, no filesystem access, no module-scoped mutable state. The module exposes one pure function:

- `extractFileLedger(messages: MessageLike[] | null | undefined, range: number[] | null | undefined): FileLedger` — iterates `range` (message indices), inspects only `assistant` messages' `toolCall` content blocks, classifies each by tool name into three accumulating Sets, and returns `{ readFiles, modifiedFiles, bashSideEffects }` each de-duplicated + lexicographically sorted.

**Input shape (load-bearing — document it; the rewind tool P1.M4.T1 MUST produce this):** `messages` is the full message list; `range` is a `number[]` of MESSAGE INDICES defining the span (NOT a `[start,end)` tuple). It is the `Unit.indices` array the rewind resolver (P1.M2.T4 transforms) produces, which includes BOTH the assistant message AND its toolResult messages — ledger filters to `role==="assistant"` because only assistant messages carry `toolCall` blocks.

### Implementation Patterns & Key Details
```ts
export function extractFileLedger(
  messages: MessageLike[] | null | undefined,
  range: number[] | null | undefined,
): FileLedger {
  const read = new Set<string>(), modified = new Set<string>(), bash = new Set<string>();
  const list = Array.isArray(messages) ? messages : [];
  const indices = Array.isArray(range) ? range : [];
  for (const i of indices) {
    if (typeof i !== "number" || !Number.isInteger(i) || i < 0 || i >= list.length) continue;
    const msg = list[i];
    if (!isRecord(msg) || readOwn(msg, "role") !== "assistant") continue;   
    const content = readOwn(msg, "content");
    if (!Array.isArray(content)) continue;
    for (const block of content) {
      if (!isRecord(block) || readOwn(block, "type") !== "toolCall") continue;
      classifyToolCall(readStringField(block, "name"), readOwn(block, "arguments"), read, modified, bash);
    }
  }
  return { readFiles: dedupeSorted(read), modifiedFiles: dedupeSorted(modified), bashSideEffects: dedupeSorted(bash) };
}
function classifyToolCall(name, args, read, modified, bash) {
  if (!name) return;
  if (READ_TOOL_NAMES.has(name)) { const p = pathArg(args); if (p) read.add(p); return; }
  if (WRITE_TOOL_NAMES.has(name)) { const p = pathArg(args); if (p) modified.add(p); return; }
  if (BASH_TOOL_NAMES.has(name)) {
    const command = isRecord(args) ? readStringField(args, "command") : "";
    if (!command || isReadOnlyBash(command)) return;            
    bash.add(command);                                          
    for (const p of extractWritePaths(command)) modified.add(p); 
  }
}
function readOwn(obj: unknown, key: string): unknown {
  if (!isRecord(obj)) return undefined;
  try { return obj[key]; } catch { return undefined; }
}
function dedupeSorted(set: Set<string>): string[] { return [...set].sort(); }

```

## Anti-Patterns to Avoid
- ❌ Don't import ANYTHING into ledger.ts (not Pi, not config, not tokens, not log) — breaks the zero-dependency
  purity the downstream consumers and the test suite depend on. Define a LOCAL MessageLike + FileLedger.
- ❌ Don't treat `range` as a [start,end) tuple — it is a number[] of message INDICES (Unit.indices from the
  resolver), which includes toolResult messages. Filter to role==="assistant" or every entry is dropped.
- ❌ Don't make bash classification SYMMETRIC. bashSideEffects must be HIGH-RECALL (whitelist + redirect +
  find-destructive detection; when in doubt include); modifiedFiles-from-bash HIGH-PRECISION (redirect targets +
  FILE_MUTATING_COMMANDS args only). Making git/node/npm/make contribute modifiedFiles breaks the pinned example.
- ❌ Don't JSON.stringify(arguments) — circular arguments would then throw. Read only .path/.file_path/.command.
- ❌ Don't normalize paths to cwd / touch the filesystem — ledger is pure; "relative to cwd" is the caller's invariant.
- ❌ Don't classify `2>&1` as a file write (it's fd-duplication) or `>=` as a redirect (it's comparison) — the
  REDIRECT_WRITE_RE negative lookahead `(?!&|=)` exists for this. `ls 2>&1 | cat` is a read-only pipeline.
- ❌ Don't classify `find -delete`/`find -exec` as read-only — FIND_MUTATING_RE guards it (find is in the read-only
  whitelist but its destructive flags flip it to side-effect).
- ❌ Don't let any function throw on adversarial input — wrap property reads in try/catch via readOwn (fail-open,
  mirroring tokens.ts). ledger sits on the rewind-tool hot path (E13).
- ❌ Don't wire ledger.ts into any handler/tool — consumers are P1.M2.T3 (notes), P1.M3.T1 (markers), P1.M4.T1
  (rewind tool); this task ships the pure module + tests ONLY.
- ❌ Don't author negative-existence or scope-boundary shell gates (`test ! -f`, `! grep`) — forbidden by G1.1/G1.2;
  scope boundaries are success criteria + a manual Level-4 gate.
- ❌ Don't delete src/ledger.ts or test/ledger.test.ts after verifying (G1.4: deliverables survive the coder's turn).
