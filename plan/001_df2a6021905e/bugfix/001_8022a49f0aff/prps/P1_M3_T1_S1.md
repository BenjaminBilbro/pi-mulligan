## Context

# PRP — BUG-004: Switch getEntries() → getBranch() in the 4 marker/label reads + branch-isolation test

## Goal

**Feature Goal:** Marker/label reads (rewinds, shrinks, turn-metrics, checkpoint labels) are scoped to the CURRENT branch only, so that after a user navigates `/tree` to a different branch, abandoned sibling-branch markers and checkpoint labels no longer apply/count/appear.

**Deliverable:** (a) Four surgical source edits swapping `ctx.sessionManager.getEntries()` → `ctx.sessionManager.getBranch()` at the exact call sites; (b) minimal mock updates in 5 test fakes + a few targeted per-test fixes so the existing 687-test suite stays green; (c) one NEW branch-isolation unit test (in `test/filter.test.ts` or a focused new file) proving sibling-branch markers are excluded from `readMarkers` and from `countRewindMarkers`.

**Success Definition:** `npx tsc --noEmit -p tsconfig.json` passes (strict mode); `npm test` is fully green (687+ passed, 0 newly broken); the new branch-isolation test asserts `readMarkers` returns ONLY branch-B markers when `getEntries()` returns A+B but `getBranch()` returns only B; no other behavior changes (the 4 consumers are order-insensitive, so no reordering).

## Why

- **Business value / user impact:** After `/tree` navigation (or any session rebind), markers created on an abandoned sibling branch currently still hide/shrink/flag messages on the *current* branch and inflate the rewind depth count and the audit checkpoint list. This is a correctness bug: the agent sees phantom rewinds/shrinks and may be refused a legitimate rewind (false maxDepth), or be shown checkpoints that don't exist on the current branch.
- **Root cause (verified):** `getEntries()` returns the raw append-only stream across EVERY branch; `getBranch()` returns only the current-branch path (leaf→root). The four readers erroneously used the cross-branch stream. See `plan/001_df2a6021905e/bugfix/001_8022a49f0aff/architecture/external_deps.md §5` and `design_decisions.md BUG-004`.
- **Scope cohesion:** This is BUG-004, one of three independent minor fixes in this milestone (BUG-004 branch scoping, BUG-005 silent persist failure, BUG-008 audit suggestion). It is surgical to existing `src/` modules — no new features, no API change. It MUST NOT touch BUG-005 (rewind tool null-check) or BUG-008 (audit suggestion line) logic.

## What

Switch the source of the four marker/label reads from `getEntries()` to `getBranch()`. All four consumers are **order-insensitive** (verified per-consumer below), so no `.slice().reverse()` or reordering is added at these sites. The try/catch + defensive `Array.isArray` guards already present are KEPT unchanged.
