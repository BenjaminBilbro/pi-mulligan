# PRP — P1.M2.T2.S1: protectedOk — add `latest:user` branch + unit tests (BUG-003 filter layer)

## Goal

**Feature Goal:** Make `protectedOk` (the filter's defense-in-depth guard, spec/06 §8) refuse any rewind whose `remove` set CONTAINS the index of the LAST `role:"user"` message, whenever `"latest:user"` is in `config.rewind.protectedRoles` (which is the DEFAULT). Today `protectedOk` only enforces `first:user`; the `latest:user` selector is read from config but never acted on, so a `checkpoint` rewind (whose resolver removes everything after the checkpoint target) can silently delete the current/latest user ask — crossing spec/06 §8's protected boundary. `last_turn` is already safe by construction (`resolveLastTurn` only removes indices AFTER `iLastUser`, keeping `iLastUser`); the GAP is checkpoint, and `protectedOk` is the filter-level backstop that closes it for ALL granularities.

**Deliverable:** A surgical edit to `src/transforms.ts:protectedOk` (add the `latest:user` branch; refactor the `if (!protectFirstUser) return true;` early-return into independent per-selector fall-through) PLUS 4 new unit tests + 1 existing-test update in `test/pipeline.test.ts`'s `protectedOk` describe block. No other files change.

**Success Definition:** `npx tsc --noEmit` clean; `npx vitest run test/pipeline.test.ts` green (existing first:user tests stay green, the 4 new tests pass, the 1 updated test passes); `npx vitest run` (full suite) green — proving `edge-cases.test.ts` E3 protectedOk tests and `filter.test.ts` are unaffected.

## Why

- spec/06 §8 mandates defense-in-depth: "a rewind that would remove the latest user message ... is refused"; "the tool refuses before persisting; the filter double-checks and no-ops". BUG-003 found the filter's `protectedOk` ignores `latest:user` entirely (only checks `first:user`), and the tool's pre-persist guard (sibling S2) covers only `last_turn`/`to_previous_prompt`. This task is the FILTER half.
- The filter is the granularity-agnostic backstop: regardless of which resolver (`resolveLastToolCallGroup` / `resolveLastTurn` / `resolveCheckpoint` / the BUG-002 `hideEntryIds` pin arm) produced a `remove` set, `protectedOk` is the single gate `filterPipeline` calls (`src/transforms.ts:883` — `if (!protectedOk(m, remove, config)) continue;`) before applying `applyRewind`. So enforcing `latest:user` HERE covers every targeting path in one place.
- Doing the filter layer first is safe even before the tool guard (S2) lands: if the tool forgets to refuse, the filter still no-ops the offending rewind (the marker persists but hides nothing). Order-independent.

## What

- `protectedOk(messages, remove, config)` signature UNCHANGED. `ProtectedConfig = { rewind: { protectedRoles: string[] } }` already exists (`src/transforms.ts:731`) and already carries `latest:user` in the default (`src/config.ts:82`). No type changes.
- After the existing `first:user` block, add a `latest:user` block: if `protectLatestUser`, compute `iLatestUser` = index of the LAST message with `role:"user"`; if `iLatestUser !== -1` AND the `remove` set CONTAINS `iLatestUser` (any `r === iLatestUser`), return `false`.
- Fail-safe: when `config.rewind.protectedRoles` is absent / empty / malformed → `protectLatestUser` defaults to **true** (enforce) — mirroring `protectFirstUser`'s existing default.
- NEVER throws (E13 discipline — it sits on the context-handler hot path via `filterPipeline`).
- Empty/non-array `remove` → `true` (vacuous, unchanged). Non-array `messages` → `true` (unchanged).

```ts
export function protectedOk(messages, remove, config): boolean {
  if (!Array.isArray(remove) || remove.length === 0) return true;
  if (!Array.isArray(messages)) return true;
  let protectFirstUser = true;
  const rewindCfg = isRecord(config) ? readOwn(config, "rewind") : undefined;
  const roles = isRecord(rewindCfg) ? readOwn(rewindCfg, "protectedRoles") : undefined;
  if (Array.isArray(roles) && roles.length > 0) {
    protectFirstUser = roles.some((r) => r === "first:user");
  }
  if (!protectFirstUser) return true;          
  let iFirstUser = -1;
  for (let i = 0; i < messages.length; i++) {
    if (isRecord(messages[i]) && readOwn(messages[i], "role") === "user") { iFirstUser = i; break; }
  }
  if (iFirstUser === -1) return true;
  let minRemove = Infinity;
  for (const r of remove) {
    if (typeof r === "number" && !Number.isNaN(r) && r < minRemove) minRemove = r;
  }
  if (!Number.isFinite(minRemove)) return true;
  return minRemove > iFirstUser;
}

```

### TARGET refactored `protectedOk` (drop-in replacement — verified by hand-trace against all tests)
```ts
export function protectedOk(messages, remove, config): boolean {
  if (!Array.isArray(remove) || remove.length === 0) return true;   
  if (!Array.isArray(messages)) return true;                        
  const rewindCfg = isRecord(config) ? readOwn(config, "rewind") : undefined;
  const roles = isRecord(rewindCfg) ? readOwn(rewindCfg, "protectedRoles") : undefined;
  const hasRoles = Array.isArray(roles) && roles.length > 0;
  const protectFirstUser  = !hasRoles || roles.some((r) => r === "first:user");
  const protectLatestUser = !hasRoles || roles.some((r) => r === "latest:user");
  if (protectFirstUser) {
    let iFirstUser = -1;
    for (let i = 0; i < messages.length; i++) {
      if (isRecord(messages[i]) && readOwn(messages[i], "role") === "user") { iFirstUser = i; break; }
    }
    if (iFirstUser !== -1) {
      let minRemove = Infinity;
      for (const r of remove) {
        if (typeof r === "number" && !Number.isNaN(r) && r < minRemove) minRemove = r;
      }
      if (Number.isFinite(minRemove) && minRemove <= iFirstUser) return false;   
    }
  }
  if (protectLatestUser) {
    let iLatestUser = -1;
    for (let i = 0; i < messages.length; i++) {
      if (isRecord(messages[i]) && readOwn(messages[i], "role") === "user") iLatestUser = i; 
    }
    if (iLatestUser !== -1 && remove.some((r) => r === iLatestUser)) return false;
  }
  return true;
}

```
NOTE on the first:user block: the original's trailing `if (!Number.isFinite(minRemove)) return true;` + `return minRemove > iFirstUser;` collapses to `if (Number.isFinite(minRemove) && minRemove <= iFirstUser) return false;` — same semantics, but refuses-and-falls-through instead of returning, so the latest:user block still runs when first:user passes. (When minRemove is non-finite / no numeric entries, first:user does not refuse; latest:user's `remove.some(r => r === iLatestUser)` also won't match non-numeric entries → final `return true`. Equivalent to the old `return true` path.)

Also UPDATE the `protectedOk` docstring to mention `latest:user` (currently says only "Enforces first:user"). Keep it concise: "Enforces first:user (min(remove) > iFirstUser) and latest:user (remove must not contain iLatestUser)."
