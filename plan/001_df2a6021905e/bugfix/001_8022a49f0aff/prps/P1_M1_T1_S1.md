# PRP for P1_M1_T1_S1

## Objective

Create src/settingsLoader.ts: a pure, Pi-free, never-throwing leaf module exporting loadMulliganSettings(opts?: { cwd?: string; isTrusted?: boolean }): unknown that reads the global ~/.pi/agent/settings.json (via os.homedir()) and, ONLY when opts.isTrusted === true, the project-local <cwd>/.pi/settings.json; extracts the `mulligan` own-key from each parsed file; applies project-local-over-global TOP-LEVEL REPLACE precedence (NOT deep-merge — spec/09 §1 'project-local wins'); and returns the merged `mulligan` value (type unknown) or undefined when neither file contributes a mulligan key. Missing/unreadable files are silently skipped; malformed JSON emits console.warn('[mulligan] settings: <path> unreadable: <msg>') and is skipped; non-object `.mulligan` values are returned as-is so config.ts:validateConfig can coerce. The module imports only node: builtins (fs/path/os) — NO pi, NO config, NO log — so it is fully unit-testable with tmp-dir fixtures. This is the foundation that lets P1.M1.T2.S1 call setConfig(loadMulliganSettings(opts)) at factory load and on every session_start, fixing BUG-001 (inert config) and BUG-006 (/reload).

## Context

## Goal

**Feature Goal**: A new, pure, Pi-free helper `src/settingsLoader.ts` that honors spec/09 §1 + README §3 by reading Mulligan's `mulligan` config from Pi's settings.json files on disk, with project-local-over-global precedence, and never throwing — so the downstream wiring task (P1.M1.T2.S1) can feed real config into the already-correct-but-starved `setConfig()`/`validateConfig()` in `src/config.ts`.

**Deliverable**: `src/settingsLoader.ts` exporting (a) `loadMulliganSettings(opts?: LoadMulliganSettingsOptions): unknown` and (b) the exported TypeScript type `LoadMulliganSettingsOptions = { cwd?: string; isTrusted?: boolean }`. Plus `test/settingsLoader.test.ts` with tmp-dir fixtures covering global-only, local-only, both (local wins), untrusted (local skipped), missing files, malformed JSON (warn + skip), non-object top-level, non-object `.mulligan`, and the undefined-when-absent → DEFAULT_CONFIG contract.

**Success Definition**: (1) `loadMulliganSettings` returns the merged `mulligan` value with local-over-global top-level-replace precedence; (2) it returns `undefined` when no file has a `mulligan` key, so `validateConfig(undefined)` yields `DEFAULT_CONFIG` (verified); (3) it NEVER throws (missing/unreadable/malformed → skip or warn+skip); (4) the module has ZERO imports from `@earendil-works/pi-coding-agent` and ZERO imports from any local `./` module (pure leaf); (5) all new unit tests pass and the existing 635-test suite stays green.

## Why

- **BUG-001 (critical):** today the factory (`src/index.ts`) never calls `setConfig`, so `getConfig()` always returns `validateConfig(undefined)` = `DEFAULT_CONFIG` — every documented knob (enabled, thresholds, maxDepth, log.file, …) is inert, and README's "`enabled: false` → all four tools refuse" is a false claim. Pi's `ExtensionAPI` exposes NO settings accessor (verified by grep of `types.d.ts` — see architecture/external_deps.md §1), so the ONLY way to honor spec/09 §1 is to read the JSON files from disk. This task builds the disk-reader; the wiring lands in P1.M1.T2.S1.
- **BUG-006 (minor):** README §3 promises config is "re-read on `/reload`". `session_start` already fires on `/reload`, so once the wiring calls `loadMulliganSettings` on every `session_start`, BUG-006 closes for free. The loader itself is reload-agnostic (no caching) so it supports this directly.
- **Why a SEPARATE module (not inline in config.ts):** keeps the fs-read + merge logic unit-testable WITHOUT pi and WITHOUT the config cache (`config.ts` caches `cachedConfig` at module scope; `vi.resetModules()` is needed to test it — see test/config.test.ts). A pure leaf is cheaper to test and respects the repo's tier convention (system_context.md: transforms/tokens/ledger/notes/config are the "Pure / Pi-FREE" tier).

### Behavioral contract (verbatim from the work item)
1. **GLOBAL path:** `path.join(os.homedir(), ".pi", "agent", "settings.json")`. Read if the file is present AND parses as valid JSON. From the parsed record, take ONLY its own `mulligan` key (ignore `packages`, `defaultModel`, etc. — this machine's global file carries them; see research notes §5). This is read UNCONDITIONALLY (global is always trusted — it is the user's own home).
2. **LOCAL path:** `path.join(opts.cwd, ".pi", "settings.json")`. Read ONLY when `opts.isTrusted === true` (strict `=== true`; untrusted/undefined → global-only, fail-safe). Same parse + extract-own-`mulligan`-key rule.
3. **MERGE = top-level REPLACE, NOT deep-merge:** if the LOCAL file has a `mulligan` own-key (any value, incl. `null`), the LOCAL `mulligan` REPLACES the GLOBAL `mulligan` entirely. Otherwise the global `mulligan` (if any) is used. spec/09 §1: "project-local wins over global via Pi's normal merge." (Top-level replace is safe because `validateConfig` fills defaults for any missing sub-keys — see design_decisions.md BUG-001 "Rejected alternatives: deep-merge".)
4. **Return:** the merged `mulligan` value typed `unknown`, or `undefined` when neither file contributes a `mulligan` own-key. A non-object `.mulligan` (e.g. `{ mulligan: 42 }` or `{ mulligan: "off" }`) is returned AS-IS — do NOT validate here; `config.ts:validateConfig` coerces (non-record raw → DEFAULT_CONFIG).
5. **NEVER throws:**
   - Missing file / unreadable (ENOENT, EACCES, EISDIR, …) → silently skip (contribute nothing).
   - Malformed JSON (SyntaxError, incl. JSONC `//` comments — verified: `JSON.parse('{//c\n"a":1}')` throws) → `console.warn("[mulligan] settings: <path> unreadable: <msg>")` then skip. Wrap the `console.warn` itself in try/catch (mirror `config.ts:warnConfig` / `log.ts:writeStderrFallback`) so logging never throws.
   - Parsed top-level is a non-record (array / primitive / null) → has no `mulligan` own-key → contribute nothing (undefined).
6. **No caching.** The caller (factory / session_start) decides when to re-read. (Spec/09 §1 "cached for the session" is implemented by `config.ts:setConfig`'s cache, NOT here.)
7. **No `pi` import, no local `./` import.** Only `node:fs` (`readFileSync`), `node:path` (`join`), `node:os` (`homedir`). This is the unit-testability invariant.

### Success Criteria
- [ ] Exports `loadMulliganSettings` + `LoadMulliganSettingsOptions` exactly as specified.
- [ ] Local-over-global top-level-replace: when both files have a `mulligan` key, the LOCAL value is returned verbatim (global ignored).
- [ ] Untrusted (`isTrusted !== true`): local file is NEVER read (global-only).
- [ ] Missing/unreadable/malformed JSON in either file: no throw; malformed → exactly one `console.warn` per malformed file with the mandated prefix; result falls through to the other file (or undefined).
- [ ] No `mulligan` key anywhere → returns `undefined` → `validateConfig(undefined)` deep-equals `DEFAULT_CONFIG`.
- [ ] Non-object `.mulligan` returned as-is (not validated, not coerced).
- [ ] ZERO imports from `@earendil-works/pi-coding-agent`; ZERO local `./` imports.

### Implementation Patterns & Key Details
```ts
import { readFileSync } from "node:fs";
import { join } from "node:path";
import { homedir } from "node:os";
export type LoadMulliganSettingsOptions = { cwd?: string; isTrusted?: boolean };
function isRecord(v: unknown): v is Record<string, unknown> {
  return typeof v === "object" && v !== null && !Array.isArray(v);
}
function mulliganValueIfPresent(obj: unknown): unknown {
  if (isRecord(obj) && Object.prototype.hasOwnProperty.call(obj, "mulligan")) {
    return obj.mulligan;
  }
  return undefined;
}
function warnUnreadable(filePath: string, err: unknown): void {
  try {
    const msg = err instanceof Error ? err.message : String(err);
    console.warn(`[mulligan] settings: ${filePath} unreadable: ${msg}`);
  } catch {
  }
}
function readMulliganKey(filePath: string): unknown {
  try {
    const txt = readFileSync(filePath, "utf8");
    const obj = JSON.parse(txt);
    return mulliganValueIfPresent(obj);
  } catch (e) {
    warnUnreadable(filePath, e);
    return undefined;
  }
}
export function loadMulliganSettings(opts?: LoadMulliganSettingsOptions): unknown {
  const globalMulligan = readMulliganKey(join(homedir(), ".pi", "agent", "settings.json"));
  if (opts?.isTrusted === true && typeof opts?.cwd === "string") {
    const localMulligan = readMulliganKey(join(opts.cwd, ".pi", "settings.json"));
    if (localMulligan !== undefined) return localMulligan; 
  }
  return globalMulligan;
}

```

- ❌ Do NOT cache the result inside the loader (the caller owns cache via config.ts:setConfig).
- ❌ Do NOT validate/coerce the mulligan value here — config.ts:validateConfig owns that. Returning non-object mulligan AS-IS is correct.

- ❌ Do NOT let console.warn throw (wrap it in try/catch like config.ts:warnConfig).
- ❌ Do NOT use truthiness to detect the mulligan key (`{mulligan:null}` IS present → null wins; use hasOwnProperty).
