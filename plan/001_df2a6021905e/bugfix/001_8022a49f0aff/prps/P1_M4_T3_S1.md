## What

### The two-signal guard (contract: "keep the two-signal guard")

Both signals must hold for a pass. Signal 1 proves the seed EXISTED + was PINNED at rewind time (so it would have leaked back if the filter broke). Signal 2 proves the seed is ABSENT on the observing inference (it was actually hidden). If only signal 2 held, the seed might be absent for an unrelated reason (e.g. the model never produced the seed reply). If only signal 1 held, the seed leaked back (BUG-001/002/003 regression).

| Signal | What it proves | F-rewind-core | F-checkpoint |
|---|---|---|---|
| **1 — tool.rewind K-text** | Seed existed + was pinned (K>=1 / K>0; not "0 messages will be hidden"; not refused). | `assert(..., "tool.rewind hid content (K>=1; not '0 messages will be hidden')", ...)` — **already HARD, keep** | `rwK0` SOFT-conditional branch — **CONVERT to straight HARD assert** |
| **2 — hiding log line** | Seed ABSENT on post-filter observing fire (status="pass"). | SOFT console.log — **CONVERT to HARD assert** | SOFT console.log — **CONVERT to HARD assert** |

### The hideEntryIds pin (READ-ONLY dependency — already landed)

```
rewind creation (src/tools/rewind.ts:resolvePreview):
  resolve the target span read-only against buildContextEntries() -> messages
  hideEntryIds = remove.map(i => indexToEntryId[i]).filter(string + non-empty)   
  marker carries hideEntryIds (src/tools/rewind.ts ~line 464: ...(hideEntryIds.length > 0 ? { hideEntryIds } : {}))
context.fire (src/transforms.ts:filterPipeline) — per rewind, oldest-first:
  if marker.hideEntryIds is present + non-empty:
    origIdxs = mapEntryIdsToMessageIndices(ORIGINAL messages, branchEntries, hideEntryIds)  
    remove = origIdxs mapped to current m-indices via origIdxOfM                          
  else: live granularity resolver (backward compat)
  -> applyRewind (gap-close, pairing-aware)

```

Because the pin resolves against the ORIGINAL messages (not the current reduced `m`), a later `-p` prompt (new user message) does NOT retarget the rewind — the seed reply committed BEFORE the rewind command stays pinned + hidden on every subsequent observing inference. This is what makes signal 2 deterministic.

### The seed flows (ALREADY in run-smoke.mjs runScenario — NO edit needed here)

- **F-rewind-core** (3-prompt): `Reply with exactly: MULLIGAN-SMOKE-SEED-HIDDEN` -> `/mulligan_smoke F-rewind-core` (last_turn rewind pins the seed) -> `Reply with exactly: OK` (observing fire; seed HIDDEN -> F-rewind-core.hiding status=pass).

The seed-canary literals (`SEED_ANCHOR = "MULLIGAN-SMOKE-SEED-ANCHOR"`, `SEED_HIDDEN = "MULLIGAN-SMOKE-SEED-HIDDEN"`) are duplicated byte-for-byte in run-smoke.mjs and smoke.ts (GOTCHA #8 — no shared module).
