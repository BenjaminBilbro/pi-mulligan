# PRP — P1.M2.T2.S2: rewind tool — checkpoint pre-persist guard refusing latest:user crossing + tests (BUG-003 tool layer)

## Goal

**Feature Goal:** Make the `mulligan_rewind` tool REFUSE (before persisting) any `checkpoint` rewind whose resolved removal set would hide the LAST `role:"user"` message (the current ask), whenever `"latest:user"` is in `config.rewind.protectedRoles` (the DEFAULT). Today the tool's step-5b guard covers ONLY the `last_turn && to_previous_prompt === true && k === 0` nuclear-across-first-user case; `checkpoint` has NO equivalent guard, so a checkpoint set before a later user message can silently delete the current ask — and although the filter (`protectedOk`, shipped in S1) now no-ops such a rewind, the TOOL still persists a stray `mulligan:rewind` marker + `mulligan:note` for a rewind that hides nothing. spec/06 §8 mandates the TOOL refuses BEFORE persisting ("the tool refuses before persisting; the filter double-checks and no-ops as defense-in-depth"). This task is the TOOL half; the FILTER half (S1) is done.

**Deliverable:** A surgical edit to `src/tools/rewind.ts`: (a) widen the module-local `resolvePreview` helper's return to also surface `remove: number[]` and `messages: MessageLike[]` (the snapshot it already builds internally — currently discarded) so the tool body can run the guard on them; (b) add the catch-path fallbacks (`remove = []`, `messages = []`) so a snapshot failure still fails-open (the filter backstops); (c) insert a new step-5c checkpoint `latest:user` guard AFTER step-5b and BEFORE `renderNote` (step 6) that computes `iLatestUser` over the snapshot and refuses iff `remove.includes(iLatestUser)`. PLUS 3 new tests in `test/tools/rewind.test.ts`. No other files change.

**Success Definition:** `npx tsc --noEmit` clean; `npx vitest run test/tools/rewind.test.ts` green (existing tests stay green, 3 new tests pass); `npx vitest run` full suite green (baseline 684 passed → 687 expected; proves no regression in the checkpoint success path, the hideEntryIds tests, the step-5b tests, or any sibling suite).

## Why

- **spec/06 §8 (defense-in-depth) is the contract:** "a rewind that would remove the latest user message … is **refused** (the tool refuses before persisting; the filter double-checks and no-ops as defense-in-depth)." The filter half (S1) is shipped; the tool half is the gap. Without it, a BUG-003 checkpoint rewind persists a marker + note for a rewind the filter will silently no-op — leaving stray artifacts in the session and a misleading success text claiming "N messages will be hidden" when the filter will hide zero.
- **The TOOL layer gives the right UX:** the agent sees a `Mulligan: refused — …` text (pattern-matchable across all refusals) and knows to pick a different target; the session stays clean (no marker, no note).
- **Order-independent w.r.t. S1:** S1 (filter) already backstops any tool that forgets. S2 makes the tool refuse up-front so no stray marker/note is written. The two layers compose; either alone is insufficient per spec/06 §8.

## What

- After the existing step-5b block in `rewindExecute` (`src/tools/rewind.ts` ~line 404), add a checkpoint-scoped guard. It fires iff ALL of: `granularity === "checkpoint"` AND `config.rewind.protectedRoles.includes("latest:user")` AND `iLatestUser !== -1` AND `remove.includes(iLatestUser)`.
- `iLatestUser` = index of the LAST message in the `resolvePreview` snapshot with `role === "user"` (loop WITHOUT `break` — overwrite each match; this is the SAME semantics as `protectedOk`'s `iLatestUser` in transforms.ts).
- On fire: `return refusal("would cross a protected message (checkpoint rewind would remove the latest user message — the current ask)", "checkpoint");` — SAME `refusal()` helper step-5b uses; produces `Mulligan: refused — would cross a protected message (checkpoint rewind would remove the latest user message — the current ask).` with `details: { granularity: "checkpoint" }`. Persist NOTHING (no `appendRewindMarker`, no `leaveNote`).
- `remove` and `messages` come from `resolvePreview` (widened return). On the resolvePreview catch path (snapshot/resolution throw), set `remove = []` and `messages = []` → `iLatestUser = -1` → guard does NOT fire → tool still succeeds best-effort (E13/E8); the filter's `protectedOk` remains the authoritative backstop when the snapshot is unavailable.
- NARROW SCOPE: `granularity === "checkpoint"` ONLY. Do NOT add a redundant guard for `last_turn` default — `resolveLastTurn` only removes indices AFTER `iLastUser` (it keeps `iLastUser`), so `latest:user` is construction-safe there. The `last_turn && to_previous_prompt` nuclear case is already handled by step-5b. `last_tool_call_group` cannot remove a user message by construction (it removes an assistant+results toolGroup).

### Success Criteria

- [ ] A `checkpoint` rewind whose resolved `remove` contains the latest-user index returns `Mulligan: refused — would cross a protected message (checkpoint rewind would remove the latest user message — the current ask).` and persists ZERO markers / ZERO notes.

- [ ] When `config.rewind.protectedRoles` omits `"latest:user"`, the guard does NOT fire (checkpoint rewind proceeds; the filter layer may still no-op, but the tool does not refuse).

### EXACT current `resolvePreview` source (src/tools/rewind.ts — the helper to widen)
```ts
function resolvePreview(
  ctx: ExtensionContext,
  params: RewindArgs,
  toolCallId: string,
): { ledger: FileLedger; k: number; hideEntryIds: string[] } {
  const branchRaw = ctx.sessionManager.getBranch();
  const branchRootToLeaf: BranchEntry[] = Array.isArray(branchRaw) ? branchRaw.slice().reverse() as BranchEntry[] : [];
  const messages: MessageLike[] = [];
  const indexToEntryId: string[] = [];
  for (const e of branchRootToLeaf) {
    const id = e && typeof e.id === "string" ? e.id : "";
    const yielded = sessionEntryToContextMessages(e as unknown as import("@earendil-works/pi-coding-agent").SessionEntry);
    for (const m of yielded) {
      messages.push(m as unknown as MessageLike);
      indexToEntryId.push(id);
    }
  }
  let remove: number[];
  if (params.granularity === "last_tool_call_group") {
    const units = partitionIntoUnits(messages);
    remove = resolveLastToolCallGroup(units, messages, toolCallId) ?? [];
  } else if (params.granularity === "last_turn") {
    remove = resolveLastTurn(messages, { to_previous_prompt: params.to_previous_prompt }, toolCallId).remove;
  } else {
    remove = resolveCheckpoint(messages, branchRootToLeaf, params.checkpoint ?? "", toolCallId)?.remove ?? [];
  }
  const ledger = extractFileLedger(messages, remove);
  const hideEntryIds = remove
    .map((i) => indexToEntryId[i])
    .filter((id): id is string => typeof id === "string" && id.length > 0);
  return { ledger, k: remove.length, hideEntryIds };
}
```
