# PRP — P1.M2.T1.S1: Data model — add `hideEntryIds?: string[]` to RewindMarker + RewindMarkerLike

## Goal

**Feature Goal:** The persisted `RewindMarker` interface (markers.ts) and the pure-tier `RewindMarkerLike` read-slice (transforms.ts) both gain an OPTIONAL `hideEntryIds?: string[]` field, with the field's purpose documented, so that later subtasks (S3 capture, S4 resolve) can pin a rewind's resolved target onto the marker at creation time (BUG-002 fix) without any backward-compatibility break.

**Deliverable:** Two surgical, type-and-comment-only edits — (a) `src/markers.ts`: add `hideEntryIds?: string[]` (+ field JSDoc) to `RewindMarker`; (b) `src/transforms.ts`: add `hideEntryIds?: string[]` (+ field JSDoc) to `RewindMarkerLike` AND replace the stale `NO \`hideEntryIds\` — that's a later fix task` clause in that interface's doc-comment. Plus type-level (+ one runtime) test assertions in `test/markers.test.ts` and `test/pipeline.test.ts`. No other file is modified.

**Success Definition:** `npx tsc --noEmit` passes (the Omit auto-gain + the markers.ts→transforms.ts structural assignability both hold), `npx vitest run` stays green (baseline 653 passed / 2 skipped PLUS the new assertions), the field exists on BOTH interfaces as `string[] | undefined`, and `filterPipeline`'s runtime behavior is provably unchanged (the field is carried, not consumed).

## Why

- **BUG-002 root cause (critical):** `filterPipeline` re-resolves each rewind's target LIVE against the current (already-reduced) message list on every inference (spec decision D7 'record a spec, not indices'). A SECOND `last_tool_call_group` rewind re-targets the FIRST rewind's resolution → originally-hidden content reappears, violating success criterion #4 ('Hidden content is never silently lost'). See `plan/001_df2a6021905e/bugfix/001_8022a49f0aff/architecture/design_decisions.md` §BUG-002.
- **The fix is to PIN each rewind's resolved target (the source `SessionEntry.id`s it hid) onto the marker at creation, then have the filter resolve against the pin.** This subtask (S1) ships ONLY the data-model field the pin needs; capture (S3) and filter resolution (S4) are separate subtasks.
- **The codebase ANTICIPATES this exact field:** the existing `RewindMarkerLike` doc-comment literally says `NO \`hideEntryIds\` — that's a later fix task` (src/transforms.ts:644). Adding it is the planned, backward-compatible step.
