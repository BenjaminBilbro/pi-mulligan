## Why

- **Business value / user impact:** BUG-007 (TEST_RESULTS.md) calls out that the deterministic smoke suite passes 9/9 but leaves the F-nudge-drift `hasNudge:true` headline assertion SOFT/model-driven — there is NO automated proof that `shouldNudge` + `injectNudge` actually fire in a real session. Shipping without an integration proof means a regression that breaks the drift path (e.g. someone breaks the `tokenBaseline` roll, the latest-metric-by-seq selection, or the `suppressCheck` window) would land silently. This task closes that gap with a deterministic, HARD-gated proof.
- **Root cause (verified by reading the source):** the nudge mechanism (`src/nudges.ts` `shouldNudge`/`injectNudge`/`suppressCheck` + `turnEndMetricHandler`, wired into `src/filter.ts:contextHandler` after `filterPipeline`) is CORRECT and unit-tested. The fix is entirely harness-side (no `src/` change).

## What

Run F-nudge-drift in a **scoped tmp cwd** with a project-local `.pi/settings.json` that sets `mulligan.nudges.driftThresholdTokens = 1` (trivially crossed by any non-empty turn). Trust the tmp project for the run via `pi -a` (a tmp cwd is not trusted by default; the project root is, via `/home/dustin/projects` in `~/.pi/agent/trust.json`). Drive a **4-prompt two-turn harness**: `/mulligan_smoke F-nudge-drift` (command — no model turn, just logs the setup marker), then 3 model turns — turn 1 establishes the baseline (`turn_end` #1, `deltaTokens:null`), turn 2 grows past the tiny threshold (`turn_end` #2, `grewOverThreshold:true`), turn 3 is the observing inference whose `context.fire` reads metric#2 → `shouldNudge` → `injectNudge` → `hasNudge:true`. Assert `hasNudge:true` HARD on the last `context.fire`, `grewOverThreshold:true` on a turn-metric, and ZERO `mulligan:nudge` entries on disk (§2.3 — the nudge is ephemeral).

### The drift nudge pipeline (READ-ONLY — already correct, the dependency)
```
turn_end (turnEndMetricHandler, src/nudges.ts):
  delta = now - rt.tokenBaseline            
  grewOverThreshold = delta != null && delta > config.nudges.driftThresholdTokens
  appendTurnMetric({deltaTokens:delta, grewOverThreshold, ...})   
  rt.tokenBaseline = now                     
context.fire (contextHandler, src/filter.ts) — runs AFTER filterPipeline:
  metric = latest mulligan:turn-metric by highest seq
  if (config.nudges.perTurnDrift && metric && shouldNudge(metric, config) && !suppressCheck(metric, markers))
    finalMessages = injectNudge(messages, metric)   
shouldNudge = grewOverThreshold || bloatHit
suppressCheck = some rewind/shrink marker.ts in (metric.ts - 10min, metric.ts]   

```
Timing: turn N's metric is appended at turn N's `turn_end`, so it is visible to turn N+1's `context.fire`. Hence TWO turns are required: turn 1 baseline (metric#1 delta=null → no nudge), turn 2 growth (metric#2 grewOverThreshold=true), turn 3 observing (`hasNudge:true`).

### Why a tmp cwd + `-a` (VERIFIED — not the project-root `.pi/settings.json`)
The repo's committed `.pi/settings.json` (project root) holds a `packages` entry pointing at `/home/dustin/projects/pi-mulligan` and has NO `mulligan` key → defaults. Mutating it would (a) risk corrupting a version-controlled file if a run is interrupted, and (b) affect ALL scenarios in the same `npm run smoke` invocation (they share cwd). A **dedicated tmp cwd** is fully hermetic: each scenario runs in its own pi process, and only F-nudge-drift gets the tmp cwd + `-a`. The tmp dir is created per-run under `SMOKE_TMP_DIR` and removed in a `finally`. Trust: a tmp cwd (e.g. `/tmp/mulligan-smoke/drift-cwd-<RUN_ID>`) is NOT trusted by default (`/tmp` is not a trusted parent in `trust.json`; non-interactive `-p` mode with `defaultProjectTrust:'ask'` IGNORES project resources — security.md). `pi -a` (`--approve`) forces `isProjectTrusted()===true` for that one run → the local `.pi/settings.json` IS read by Mulligan's `loadMulliganSettings`. (The project root is already trusted via `/home/dustin/projects:true` in trust.json, so the other 8 scenarios need no `-a`.)

### SPIKE PROOF (run 2026-08-11 against this repo + glm-5.2)
A tmp cwd `/tmp/mulligan-drift-spike/.pi/settings.json` = `{"mulligan":{"nudges":{"driftThresholdTokens":1}}}` was run via `cd /tmp/mulligan-drift-spike && pi -ne -a -e <abs>/src/index.ts -e <abs>/test/integration/smoke.ts --session-id <id> -p ...`. Two flows:
